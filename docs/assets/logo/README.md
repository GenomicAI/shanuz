# The truecell logo

Every file here is generated by [`tools/make_logo.py`](../../../tools/make_logo.py).
Edit the script, not the SVGs:

```bash
python tools/make_logo.py --png
```

Without `--png` it writes only the SVGs, which are the actual deliverable; the
raster exports need Chrome to render and Pillow to downsample.

## The idea

`truecell` is a port of Seurat, and Seurat is named for Georges Seurat, the
pointillist. So the mark is built the way he built a picture: **every dot is a
cell, and the point cloud resolves into a lowercase `c`.**

The `c` is two arcs meeting at the waist, each in a different colour — the R
implementation and the Python one, forming one continuous shape. That split is
not decoration; it is what the package is.

The letter is a `c` for `cell`, and it is also the letter the wordmark's own `c`
draws: the mark is not an ornament sitting beside the name, it is a letter of it,
enlarged. When the package was called `shanuz` the same mark was an `s`, drawn on
a hand-placed skeleton; the rename is what turned it into an arc, and the arc is
the better shape for the job — see *How it is built*.

## Which file to use

| File | Use it for |
|---|---|
| `truecell-mark.svg` | The primary mark. Docs header, PyPI, GitHub avatar, slides. |
| `truecell-lockup.svg` | Mark plus wordmark, horizontal. README headers, talk titles, anywhere the name needs to appear with the mark. |
| `truecell-wordmark.svg` | The name alone, where the mark already appears nearby. |
| `truecell-hex.svg` | The hexagon sticker. This is a port of an R package, and hex is that ecosystem's convention. |
| `truecell-glyph.svg` | The simplified mark — the same `c`, drawn as one stroke instead of dots. Use it **below about 48 px**, where the dots silt up. |
| `truecell-glyph-open.svg` | The glyph with no tile of its own, for a ground that is already coloured. This is the documentation header's logo. |
| `favicon.svg` | Same art as the glyph, named for its job. |

Every one has an `-inverse` twin. The rule is simple: the plain file is for a
**light** page (it has a pine tile and pine ink), the `-inverse` file is for a
**dark** page (cream tile, cream ink). Neither is "the dark version of the logo"
— they are the same logo, prepared for the two grounds.

The one place both twins appear at once is the repository README, whose lockup
is a `<picture>`: GitHub has a dark mode, and the reader picks the ground.

Raster exports: `truecell-mark-{512,256,128}.png`, `truecell-hex-512.png`,
`truecell-lockup-1200.png` and `truecell-lockup-inverse-1200.png`,
`apple-touch-icon.png` (180), and `favicon-{48,32,16}.png`. All are RGBA.

## Palette

The documentation site's, unchanged — see `docs/stylesheets/extra.css`. The
logo and the site are one system, and the colours should stay that way.

| Token | Hex | Role |
|---|---|---|
| Pine | `#17423a` | Ground on light pages; ink on dark ones |
| Amber | `#b2560d` | The lower lobe, on a light ground |
| Amber soft | `#eb9d5c` | The lower lobe, on a dark ground |
| Cream | `#f3f6f4` | Ground on dark pages; ink on light ones |

Amber is the only saturated colour and it is spent on one thing: the second
lobe. Do not add a third accent.

## Clear space and minimum size

Keep clear space of **one quarter of the mark's height** on all sides. In the
lockup that distance is already built in between the mark and the wordmark.

Minimum sizes: the pointillist mark **48 px**; the glyph **16 px**; the lockup
**140 px** wide. Below 48 px, switch to the glyph rather than shrinking the mark
— that is what it is for.

## Don'ts

- Don't recolour it. The two lobes carry the meaning.
- Don't put the pointillist mark on a photograph or a mid-tone; it needs its own
  ground, which is why it ships with a tile.
- Don't stretch the lockup, or reset the wordmark in a real font — the letters
  are drawn to match the mark's construction, and no font matches them.
- Don't rebuild the mark by hand. It is generated from a seed; re-run the script.

## How it is built

The spine is a single circular arc, opened on the right — the terminals stop at
55° and 305° rather than at 90° and 270°, so the aperture reads as a gap and not
as a half circle. The colour split sits at half the arc length, and on a
constant-radius arc that point is exactly the left extremity, so the split lands
on the axis of symmetry with no fudge factor.

That property is why the arc replaced the `s` rather than the `s` being bent into
a `c`. The `s` had to earn the same symmetry the hard way, through a hand-placed
skeleton smoothed by a centripetal Catmull-Rom spline and given 180° rotational
symmetry by hand; an arc gets it for free. The spline code is still in the script
because the `s` letterform still uses it, and `wordmark(word=...)` will set any
word it is given.

The wordmark is monoline geometric lowercase built from the same circles and
emitted as sampled polylines, so **there is no font to license and none to fail
to load**. Its `c` reuses the mark's own construction, split into the same two
colours at the same midpoint — it is the only letter in `truecell` that is one
unbroken arc, so it is the only one whose midpoint is a place the colour can
change without the join looking arbitrary. The `l` carries no advance of its own;
the tracking alone sets its gap, which is what keeps `ll` evenly spaced.

The favicon is solid rather than dotted because that is what survived being
rendered at 16 px and looked at. The dots do not.
