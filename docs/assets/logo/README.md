# The shanuz logo

Every file here is generated by [`tools/make_logo.py`](../../../tools/make_logo.py).
Edit the script, not the SVGs:

```bash
python tools/make_logo.py --png
```

Without `--png` it writes only the SVGs, which are the actual deliverable; the
raster exports need Chrome to render and Pillow to downsample.

## The idea

`shanuz` is a port of Seurat, and Seurat is named for Georges Seurat, the
pointillist. So the mark is built the way he built a picture: **every dot is a
cell, and the point cloud resolves into a lowercase `s`.**

The `s` is two lobes that meet at the waist, each in a different colour — the R
implementation and the Python one, forming one continuous shape. That split is
not decoration; it is what the package is.

## Which file to use

| File | Use it for |
|---|---|
| `shanuz-mark.svg` | The primary mark. Docs header, PyPI, GitHub avatar, slides. |
| `shanuz-lockup.svg` | Mark plus wordmark, horizontal. README headers, talk titles, anywhere the name needs to appear with the mark. |
| `shanuz-wordmark.svg` | The name alone, where the mark already appears nearby. |
| `shanuz-hex.svg` | The hexagon sticker. This is a port of an R package, and hex is that ecosystem's convention. |
| `shanuz-glyph.svg` | The simplified mark — the same `s`, drawn as one stroke instead of dots. Use it **below about 48 px**, where the dots silt up. |
| `shanuz-glyph-open.svg` | The glyph with no tile of its own, for a ground that is already coloured. This is the documentation header's logo. |
| `favicon.svg` | Same art as the glyph, named for its job. |

Every one has an `-inverse` twin. The rule is simple: the plain file is for a
**light** page (it has a pine tile and pine ink), the `-inverse` file is for a
**dark** page (cream tile, cream ink). Neither is "the dark version of the logo"
— they are the same logo, prepared for the two grounds.

The one place both twins appear at once is the repository README, whose lockup
is a `<picture>`: GitHub has a dark mode, and the reader picks the ground.

Raster exports: `shanuz-mark-{512,256,128}.png`, `shanuz-hex-512.png`,
`shanuz-lockup-1200.png` and `shanuz-lockup-inverse-1200.png`,
`apple-touch-icon.png` (180), and `favicon-{48,32,16}.png`. All are RGBA.

## Palette

The documentation site's, unchanged — see `docs/stylesheets/extra.css`. The
logo and the site are one system, and the colours should stay that way.

| Token | Hex | Role |
|---|---|---|
| Pine | `#17423a` | Ground on light pages; ink on dark ones |
| Amber | `#b2560d` | The lower lobe, on a light ground |
| Amber soft | `#eb9d5c` | The lower lobe, on a dark ground |
| Cream | `#f3f6f4` | Ground on dark pages; ink on light ones |

Amber is the only saturated colour and it is spent on one thing: the second
lobe. Do not add a third accent.

## Clear space and minimum size

Keep clear space of **one quarter of the mark's height** on all sides. In the
lockup that distance is already built in between the mark and the wordmark.

Minimum sizes: the pointillist mark **48 px**; the glyph **16 px**; the lockup
**140 px** wide. Below 48 px, switch to the glyph rather than shrinking the mark
— that is what it is for.

## Don'ts

- Don't recolour it. The two lobes carry the meaning.
- Don't put the pointillist mark on a photograph or a mid-tone; it needs its own
  ground, which is why it ships with a tile.
- Don't stretch the lockup, or reset the wordmark in a real font — the letters
  are drawn to match the mark's construction, and no font matches them.
- Don't rebuild the mark by hand. It is generated from a seed; re-run the script.

## How it is built

The spine is a centripetal Catmull-Rom spline through a hand-placed skeleton
with exact 180° rotational symmetry about the waist. The symmetry is load
bearing: it puts the waist at precisely half the arc length, so the two-lobe
colour split needs no fudge factor. Two swept arcs — the obvious construction
for an `s` — close into a ring and read as a "no entry" sign.

The wordmark is monoline geometric lowercase built from the same circles and
emitted as sampled polylines, so **there is no font to license and none to fail
to load**. Its `s` reuses the mark's own skeleton, split into the same two
colours at the same waist.

The favicon is solid rather than dotted because that is what survived being
rendered at 16 px and looked at. The dots do not.
